# Доменная модель

Система мониторинга криптовалютных операций с применением искусственного интеллекта.
Первая версия: блокчейн **Ethereum**.

Принцип проектирования: сначала строится платформа мониторинга (данные → риск →
алерты → интерфейс), и только затем добавляется модуль ИИ. ИИ — один из инструментов
внутри системы, а не её единственная ценность.

---

## Сущности первой версии

### 1. BlockchainNetwork
Поддерживаемые блокчейн-сети. Заведена сразу, хотя в первой версии активна только
Ethereum — чтобы позже добавить Bitcoin, TRON, BNB Chain без переделки модели.

| Поле | Тип | Описание |
|------|-----|----------|
| id | int (PK) | идентификатор |
| name | string | название (Ethereum, Bitcoin, ...) |
| symbol | string | символ (ETH, BTC, ...) |
| is_active | bool | используется ли сейчас |
| created_at | datetime | дата добавления |

### 2. Wallet
Криптокошелёк (адрес). Хранит агрегированную статистику поведения и общий риск-скор.

| Поле | Тип | Описание |
|------|-----|----------|
| id | int (PK) | идентификатор |
| address | string | адрес кошелька |
| network_id | int (FK → BlockchainNetwork) | сеть |
| first_seen_at / last_seen_at | datetime | первая/последняя активность |
| transaction_count | int | число транзакций |
| total_received / total_sent | decimal | суммарные объёмы |
| risk_score | decimal | агрегированный риск (обновляется движком) |
| is_flagged | bool | помечен как подозрительный |
| label | string? | метка: биржа / миксер / мошенник / null |
| created_at / updated_at | datetime | служебные поля |

### 3. Transaction
Отдельная операция в блокчейне. Сердце системы.

| Поле | Тип | Описание |
|------|-----|----------|
| id | int (PK) | идентификатор |
| tx_hash | string | хеш транзакции |
| network_id | int (FK → BlockchainNetwork) | сеть |
| sender_wallet_id | int (FK → Wallet) | отправитель |
| receiver_wallet_id | int (FK → Wallet) | получатель |
| amount | decimal | сумма |
| currency | string | валюта (ETH) |
| gas_fee | decimal | комиссия |
| block_number | int | номер блока |
| transaction_timestamp | datetime | время операции |
| status | string | статус (success / failed) |
| created_at | datetime | дата записи в систему |

### 4. Rule
Правило расчёта риска для Rule Engine. Вынесено в отдельную сущность, чтобы менять
правила без переписывания кода.

| Поле | Тип | Описание |
|------|-----|----------|
| id | int (PK) | идентификатор |
| name | string | название (например, «Большая сумма») |
| description | text | описание условия |
| score | decimal | вклад правила в риск |
| is_active | bool | включено ли правило |
| created_at | datetime | дата создания |

### 5. TransactionRisk
Оценка риска **отдельной транзакции**. Хранится историей (каждый пересчёт — новая
запись). Риск, посчитанный правилами и ИИ, хранится раздельно.

| Поле | Тип | Описание |
|------|-----|----------|
| id | int (PK) | идентификатор |
| transaction_id | int (FK → Transaction) | транзакция |
| rule_score | decimal | вклад правил |
| ml_score | decimal | вклад модели ИИ |
| final_score | decimal | итоговый риск |
| risk_level | enum | LOW / MEDIUM / HIGH / CRITICAL |
| created_at | datetime | время расчёта |

### 6. WalletRisk
Оценка риска **кошелька в целом** (накопленная картина поведения). Нужна потому, что
кошелёк может быть подозрительным, даже если каждая отдельная его транзакция невинна
(пример: тысячи мелких операций, связь с миксером).

| Поле | Тип | Описание |
|------|-----|----------|
| id | int (PK) | идентификатор |
| wallet_id | int (FK → Wallet) | кошелёк |
| rule_score | decimal | вклад правил |
| ml_score | decimal | вклад модели ИИ |
| final_score | decimal | итоговый риск |
| risk_level | enum | LOW / MEDIUM / HIGH / CRITICAL |
| created_at | datetime | время расчёта |

### 7. Alert
Оповещение, которое видит аналитик. Создаётся при превышении порога риска. Ссылается
либо на TransactionRisk, либо на WalletRisk (через target_type).

| Поле | Тип | Описание |
|------|-----|----------|
| id | int (PK) | идентификатор |
| risk_id | int (FK → TransactionRisk / WalletRisk) | источник риска |
| target_type | enum | transaction / wallet |
| title | string | краткий заголовок |
| description | text | описание |
| level | enum | low / medium / high |
| status | enum | open / in_progress / closed / false_positive |
| created_at | datetime | создание |
| resolved_at | datetime? | закрытие |

## Задел на будущее (НЕ реализуется в первой версии)

Эти сущности заложены в архитектуру, но реализуются позже, чтобы не тормозить
запуск основной платформы мониторинга к сроку.

- **User** — сотрудник ДЭР (роли: Analyst / Investigator / Administrator),
  аутентификация и права доступа.
- **Investigation** — расследование, группирующее несколько алертов; создаётся
  пользователем.

---

## Ключевые архитектурные решения

1. **BlockchainNetwork заведена сразу** — расширяемость на другие сети без переделки.
2. **Риск считается и для транзакций, и для кошельков** — это два разных вопроса,
   которые нельзя свести один к другому.
3. **Две отдельные таблицы риска** (TransactionRisk, WalletRisk) вместо одной общей —
   честные внешние ключи, целостность гарантируется базой данных.
4. **rule_score / ml_score / final_score хранятся раздельно** — Rule Engine и AI Engine
   пишут свой вклад независимо; ИИ добавляется вторым этапом, не ломая модель.
5. **User и Investigation отложены** — главная ценность (данные → риск → алерты)
   доводится до рабочего состояния в первую очередь.
